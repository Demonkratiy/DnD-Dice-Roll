# Тестирование: два слоя и зачем они

В проекте **два уровня тестов**, и выбор уровня — не вкусовщина, а следствие того,
_что_ именно проверяем.

| Слой | Инструмент | Среда | Что проверяет |
| ---- | ---------- | ----- | ------------- |
| Юнит / компонентные | **Vitest** + Testing Library | jsdom | домен, reducer, контракт компонентов, доступность, клавиатура |
| End-to-end | **Playwright** | реальный Chromium | «геометрию»: layout, scroll-snap, координаты клика, CSS-переходы |

## Почему два, а не один

**jsdom не считает layout.** В среде Vitest `getBoundingClientRect()` и `scrollTop`
всегда возвращают нули, CSS scroll-snap и переходы высоты не работают. Поэтому всё,
что зависит от _реальной геометрии на экране_, в jsdom непроверяемо — там тест дал бы
ложную зелёную галочку. Такие сценарии уходят в Playwright, где есть настоящий движок
рендеринга.

Всё остальное (рендер опций, `aria-checked`, реакция на стрелки, вызовы `onChange`)
быстрее и дешевле проверять в Vitest — браузер для этого не нужен.

### Показательный пример — `WheelPicker`

Был баг «прыжка»: клик по соседнему пункту барабана выбирал пункт _через один_.
Причина чисто геометрическая — высота «рельс» менялась при раскрытии, и во время
CSS-перехода `scrollTop` разъезжался с индексом выбранного пункта (подробнее об
устройстве барабана — в [animation-and-gesture.md](./animation-and-gesture.md)).

- В Vitest такой баг **невидим** (нет layout) → там покрыт только контракт:
  [WheelPicker.test.tsx](../src/shared/ui/WheelPicker.test.tsx).
- В Playwright он **воспроизводится мышью по координатам** → регрессия зафиксирована:
  [e2e/wheel-picker.spec.ts](../e2e/wheel-picker.spec.ts).

## Конвенции e2e (Playwright)

- **Минимализм.** e2e — только там, где нужен настоящий браузер. Не дублируем в нём
  то, что уже покрыто в Vitest. Один браузер (Chromium), без кросс-браузерного
  перегруза — баги тут про layout, а не про вендорные различия.
- **Чёрный ящик.** Ожидаемые видимые строки (подписи пунктов) пишем в тесте
  **литералами**, а не импортируем из словаря локализации. Иначе тест проверяет
  «равно самому себе» и не поймает перепутанный/неверный перевод.
- **Структуру — из DOM, не из хардкода.** Число опций, порядок и т.п. читаем со
  страницы (`getByRole('radio').count()`), чтобы тест не ломался при добавлении
  нового варианта. Дублируем _данные, которые проверяем_, но не _структуру
  реализации_.
- **Изоляция от Vitest.** `e2e/` исключён из Vitest ([vite.config.ts](../vite.config.ts))
  и из общего ESLint-конфига ([eslint.config.js](../eslint.config.js)) — там своя
  Playwright-среда со своими глобалами.

## Команды

```bash
npm run test        # Vitest (однократный прогон)
npm run test:watch  # Vitest в watch-режиме
npm run test:e2e    # Playwright e2e (сам поднимает dev-сервер через webServer)
npm run test:e2e:ui # Playwright в UI-режиме (визуальная отладка)
```
