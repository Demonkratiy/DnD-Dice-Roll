# AGENTS.md — DnD Dice Roller

> Этот файл — **основной ориентир** для агента и разработчиков. Если контекст
> переполнен или ты только что подключился к проекту — начни отсюда.

## 1. Что это за проект

Веб-приложение для броска кубиков D&D (d4, d6, d8, d10, d12, d20, d100).
Задача формально простая, но **главная ценность — эмоции и стиль**: красивый,
тактильный бросок кубика, приятные анимации, аккуратный минималистичный UI.

Проект учебный: важны **чистая архитектура, читаемость, комментарии и документация**.

## 2. Ключевое видение (не нарушать без обсуждения)

- **Кубик — главный объект сцены.** Бросок совершается жестом по самому кубику:
  - тап / клик = бросок;
  - зажать = «тряска» (кубик дрожит), отпустить = запускается перебор форм;
  - чем дольше/сильнее зажатие — тем дольше анимация и быстрее стартовая смена
    форм, плавно замедляясь (ease-out). **На результат это НЕ влияет** — RNG честный.
- **Перебор форм** во время броска: быстрая смена силуэтов **в рамках одного
  номинала** (бросаем d20 → мелькают вариации d20). 3 вариации силуэта на номинал.
  - _TODO (задел):_ подмешивать тематические силуэты (монета, оружие, руны, символы
    магии) через отдельный «провайдер кадров» (`FrameProvider`). Реализуем позже.
- **Стиль:** плоский минимализм. Силуэты — SVG, окрашиваются через CSS-переменные.
- **Темы:** переключаются в настройках; реализованы на CSS-переменных + `data-theme`
  на `<html>`. Старт — тема `flat`; задел — `neon` и др.
- **Компоновка** (один центрированный столбец, адаптив без перестройки, сверху вниз):
  1. Верхняя строка: имя игрока (слева) · ⚙ меню/настройки (справа).
  2. **Сцена** с кубиком (основная площадь) + крупный результат.
  3. Лента выбора номинала: выбранный — подсветка/ореол + чуть крупнее.
  4. Контролы броска: количество кубиков · модификатор +/− · режим adv/dis (для d20).
  5. _(опц.)_ окно логов — выезжающий снизу **Drawer** с хэндлом-«пером»; включается
     в настройках. Постоянной истории на экране нет.
- **Доступность:** уважать `prefers-reduced-motion`; есть опция «отключить анимации»;
  бросок доступен с клавиатуры (Space/Enter).

## 3. Онлайн и мультиплеер

Сейчас — **локальное приложение без бэкенда**. Но архитектура обязана делать будущий
**мультиплеер** (совместные игры с игроками и ГМ) дешёвым в добавлении. Принципы:

1. **Бросок — чистая, сериализуемая доменная функция.** `rollDice(request, rng)`
   возвращает самодостаточный объект-событие (id, нотация/запрос, кости, итог,
   timestamp, автор). Без React/DOM внутри.
2. **RNG инъектируется** как зависимость (на будущее — seed от сервера/ГМ).
3. **Источник бросков за интерфейсом** `RollSource`: сейчас `LocalRollSource`,
   позже `RemoteRollSource` (WebSocket). UI не знает, локально это или по сети.
4. **Понятия `player`/`room` заложены в типах** с самого начала.
5. **Состояние — через reducer/события** (`ROLL_ADDED`, …): тот же редьюсер позже
   обработает события из сети.

## 4. Архитектура: FSD-lite (Feature-Sliced Design, облегчённая)

Импорты — **только вниз**: `app → features → entities → shared`.

```
src/
  app/         точка входа (main.tsx), App.tsx, провайдеры, глобальные стили
  features/    пользовательские сценарии и крупные блоки UI:
               stage (сцена), dice-picker, roll-controls, settings, log
  entities/    бизнес-сущности: die, roll, player (типы + чистая логика + model)
  shared/
    ui/        ui-kit: Button, IconButton, Stepper, Segmented, Drawer, Switch
    lib/       утилиты и хуки: rng, usePressAndShake, useRollAnimation, useReducedMotion
    services/  RollSource (+ LocalRollSource, TODO RemoteRollSource), audio
    theme/     css/ (base + palettes + animations), shape/ (shapes + ShapeProvider), color/ (colors + ColorProvider)
    config/    константы (набор кубиков, дефолты)
```

- Внутри слайса — сегменты `ui/ model/ lib/ api/`.
- У каждого слайса — `index.ts` как **public API** (импортируем из слайса только через него).
- Алиасы путей: `@app/* @features/* @entities/* @shared/*`.

## 5. Технологии

- **React 19 + Vite + TypeScript** (strict).
- **CSS Modules** для стилей компонентов + глобальные **CSS-переменные** для тем.
- **Vitest** + Testing Library для тестов (домен и reducer — обязательно покрыты).

## 6. Команды

```bash
npm run dev        # дев-сервер
npm run build      # tsc -b + vite build (продакшен-сборка)
npm run preview    # предпросмотр прод-сборки
npm run lint       # ESLint
npm run typecheck  # проверка типов без эмита
npm run test       # Vitest (однократный прогон)
npm run test:watch # Vitest в watch-режиме
```

## 7. Конвенции

- Доменная логика (`entities`, `shared/lib`) — **чистая и тестируемая**, без побочных
  эффектов и без обращений к DOM/React.
- Любая случайность — только через инъекцию `Rng`, **никогда** напрямую `Math.random()`
  в доменном коде.
- Данные броска должны оставаться **сериализуемыми** (готовность к передаче по сети).
- Комментарии и документация приветствуются (учебный проект) — поясняем «почему», а не «что».
- Не добавляем фич сверх запрошенного; помечаем будущие расширения как `TODO`.
- Технические разборы «как что реализовано» складываем в [`dev-wiki/`](./dev-wiki/README.md)
  (Markdown + диаграммы Mermaid). Новый документ — добавляем ссылку в `dev-wiki/README.md`.
